## Implemented scope

Content/plan version 7 adds one independent Rootbound opportunity at depth 6 and above: a 25 percent roll per eligible floor, with at most one nonhidden, unreserved `trap_thorns` room selected. This is not a separate roll for every room. Existing topology, old slot/random-call order, theme selection, encounter packs, chests and checkpoint placement retain their contracts. Profile/save version 7 is unchanged. The selected room's one first-entry rolling attempt replaces only its initial legacy-root opportunity; native refusal is a harmless omission without a retry, fallback root or stacked trap.

The authored v3 profile has a two-second warning, six-metre path, 0.65-metre radius, three metres/second speed and one whole-pass damage identity. Base damage 14 receives the frozen depth scaling once. The immutable source and full issued lane remain fixed; active danger shrinks from the actual stone centre to the original endpoint, while damage checks only actual swept contact. An active delta above 0.25 seconds cancels harmlessly. Directional hits use the validated segment-start approach origin through a backward-compatible CombatRules argument.

Native admission and each active segment verify the exact owned continuous floor, its captured frame and the grounded sphere. Only the verified supporting floor and established foreign-world colliders are excluded from the sphere query. Same-world walls, chests, stationary blockers and low obstacles remain relevant. Actual native tests cover thin blockers, support/frame/source loss, endpoint overlap, translated rooms, routes and both camera modes. The stone is a moving damaging volume with passive presentation, not a physical blocker or projectile.

Private source, reservation and accepted/terminal identities survive cancellation and same-wrapper replacement callbacks without allowing an old cast to erase a newer one. Existing typed/legacy hazard behavior remains covered. Guardian and Mystic scenarios use actual movement, paid reaction delays, both cameras and unchanged clearance/decision/query limits. No stone reward, item, currency, kill XP, pet finding, journal or objective grant is introduced.

Progression checks preserve actual pack/chest rewards, collection, early Return and a later real boss/full extraction. Return is exercised in another admitted room: this batch does not install a spring in the rolling chamber or claim a transaction behind the stone there. A naturally pending local patrol completes its full warning, is registered alive, blocks Return, and is cleared through the existing death/grant path before Return opens.
